# Velocity Harness 0.2.1

Tauri 2 + React + Rust. Linux — самостоятельный AI-harness с интерфейсом. Android — самостоятельный AI-чат или клиент Linux-компьютера.

## Запуск

- Android: ARM64 APK, Android 7+ и современный Android System WebView. APK подписан development/distribution ключом; это не Play Store release identity.
- Linux x86_64: сделать AppImage исполняемым и запустить. Сборка сделана на Amazon Linux 2023, glibc 2.34. Для старых glibc-систем пересоберите на самой старой поддерживаемой системе с WebKitGTK 4.1.

```sh
chmod +x Velocity-Harness-0.2.1-linux-x86_64.AppImage
./Velocity-Harness-0.2.1-linux-x86_64.AppImage
# Без FUSE:
./Velocity-Harness-0.2.1-linux-x86_64.AppImage --appimage-extract-and-run
```

В настройках провайдера укажите протокол OpenAI-compatible или Anthropic-compatible, Base URL, ключ и ID модели. Base URL должен включать `/v1`, если этого требует провайдер. Для API используйте HTTPS; HTTP нужен для доверенных локальных серверов, например Ollama / LM Studio. Ключ может быть пустым для провайдера без авторизации. API endpoint не должен содержать логин, query или fragment. Redirects не принимаются: укажите конечный URL.

Совместимость с API не означает поддержку tool calling любой моделью. Веса моделей не включены: локальные модели подключаются через совместимый API, который уже запущен на вашем устройстве или компьютере.

## Папки и чаты

На Linux кнопка «Открыть папку» вызывает настоящий системный выбор каталога. Rust получает canonical path и ищет уже зарегистрированный проект; повторный выбор не создаёт дубль. Все чаты связаны с проектом и показаны внутри его аккордеона. Путь конкретного чата не меняется при открытии другой папки.

История и проекты сохраняются в `history.json` внутри системного app-data каталога `app.velocity.harness`. Обычно это `$XDG_DATA_HOME/app.velocity.harness` либо `~/.local/share/app.velocity.harness` на Linux и приватный каталог приложения на Android. История не записывается в исходники вашего проекта. Хранилище — локальный JSON с атомарной заменой, не SQLite. На Unix каталог имеет mode 0700, файл 0600.

API-ключи сохраняются через системное защищённое хранилище (`tauri-plugin-secure-keystore`, закреплённая версия 0.0.3-beta.1): Android Keystore + AES-GCM; Linux Secret Service (разблокированный GNOME Keyring / совместимый KWallet). В `history.json` ключей нет. Они загружаются в движок при первом локальном RPC после запуска, но не возвращаются в metadata и не отправляются на телефон. Пустое поле при сохранении сохраняет прежний ключ только для того же имени, протокола и Base URL. Смена URL не переиспользует старый ключ. Кнопка «Удалить сохранённый ключ» очищает хранилище и память. При недоступном системном хранилище приложение сообщает об ошибке и оставляет введённый ключ только на этот запуск, без небезопасного файлового fallback. LAN-токены остаются только в памяти. Установленная версия 0.2.0 не сохраняла ключ, поэтому после обновления его нужно один раз ввести и сохранить. История содержит обычный текст сообщений и результаты инструментов, не зашифрована. Не вставляйте секреты и не прикладывайте файлы с ключами.

Черновики живут в памяти интерфейса и сохраняются при переключении чатов/настроек, но не после закрытия приложения. Полученный частичный ответ сохраняется при штатной отмене и ошибке; при аварийном завершении процесса последние ещё не записанные дельты могут потеряться.

## Реальный стриминг

Движок отправляет `stream: true` в OpenAI Chat Completions и Anthropic Messages. Обрабатывает текстовые дельты, фрагментированные аргументы tool calls, завершение, ошибки и отмену. Если совместимый endpoint возвращает обычный JSON вместо SSE, он тоже принимается, но ответ такого endpoint появится целиком.

Нативный интерфейс получает события активного запуска через RPC polling каждые 150 мс. Это реальные дельты провайдера, не анимация заранее полученного ответа. Каждое слово получает fade-in, курсора `|` нет. Неполный последний фрагмент буферизуется до границы слова или короткого ожидания. Кнопка остановки отменяет активный сетевой запрос. Успевшие выполниться действия не откатываются.

Разрешения относятся к чату, изменяются без перезапуска ответа и не очищают pending approval. Ожидающее действие не исполняется автоматически при смене режима.

## Подтверждение и diff

Для всех привилегированных действий используется общий React ApprovalCard.

- `edit_file`: реальное содержимое файла до изменения и запланированный результат. Показан unified diff удалённых/добавленных строк.
- `write_file`: diff существующего файла либо полностью новый текст как добавленные строки.
- `shell`: команда и предупреждение о неограниченном доступе к системе.

Preview готовится на Linux до запроса разрешения. Перед записью содержимое сравнивается с тем, что было показано в diff. Если файл изменился или новый файл уже появился, операция не применяется; необходимо получить новую правку. Очень большой diff отображается с ограничением 1200 строк, поэтому разделяйте большие изменения. Файловые операции ограничены 256 KB.

Режимы:

| Режим | Поведение |
| --- | --- |
| С подтверждением | Чтение автоматически; изменения и shell требуют разрешения |
| Только чтение | Чтение разрешено; запись и shell заблокированы |
| Доверять проекту | Новые правки внутри проекта выполняются автоматически; shell всегда требует разрешения |

## Инструменты

`read_file`, `list_files`, `search_files`, `grep`, `edit_file`, `write_file`, `shell`. Дополнительно `recommend_options` предлагает варианты плана через RecommendationCard; выбор отправляет ответ пользователя, а не выполняет команду сам.

Пути файловых инструментов относительны проекту. Абсолютные пути, `..`, выходы через symlink и типичные секретные пути (`.env*`, `.ssh`, `.aws`, `.gnupg`, `.npmrc`, `credentials`, приватные SSH-ключи) запрещены. Поиск пропускает `.git`, `node_modules`, `target` и ограничен 100 результатами. Shell имеет лимит 30 секунд, вывод ограничен.

**Shell не является песочницей.** Команда запускается от вашего имени и может работать вне проекта, удалять файлы, делать сетевые запросы и запускать дочерние процессы. Не запускайте приложение от root. Отмена останавливает прямой процесс, но не гарантирует уничтожение всех фоновых потомков. Подтверждение не защищает от враждебного локального процесса, который меняет symlink между проверкой и записью.

## Linux + Android

1. Linux: Настройки → Устройства → Включить LAN-сервер. До нажатия сервер не слушает порты.
2. TCP 8787 для API, UDP 8788 для discovery. Разрешайте их в firewall только для доверенной сети.
3. Android: Найти в локальной сети. Выберите компьютер либо введите его LAN IP вручную.
4. Скопируйте токен из Linux и подключитесь.
5. Список проектов, чатов, провайдеров и активный запуск берутся с Linux. API-ключи не передаются на телефон. Выбрать уже сохранённый провайдер можно с телефона; создавать/изменять его параметры — на Linux.
6. Подтверждения доступны на обоих устройствах. События своего активного запуска обновляются каждые 150 мс; состояние второго клиента обнаруживается периодической синхронизацией примерно раз в 3 секунды.

Discovery может блокироваться VPN, firewall или Wi-Fi client isolation. Прямой HTTP разрешён только для локальных IP/localhost. Для удалённого URL нужен HTTPS reverse proxy либо доверенный VPN. Встроенных TLS-сертификатов нет. Не пробрасывайте HTTP 8787 в интернет.

Токен даёт доверенному устройству доступ к проектам, истории и подтверждениям. Это не независимый второй фактор. Остановка LAN-сервера закрывает новые подключения и инвалидирует токен, но не откатывает уже начатый run или выполненные команды. Останавливайте активный run отдельно.

Android без Linux работает как чат с API-провайдером; компьютерные инструменты доступны только через Linux.

## Alpine compat

`Velocity-Harness-0.2.1-alpine-compat-x86_64.AppImage` содержит glibc userspace и статический PRoot. Это **не нативная musl-сборка**. Системная glibc/gcompat не требуется, но нужен графический X11/Wayland-сеанс, поддержка ptrace и совместимый графический стек. При отсутствии FUSE используйте `--appimage-extract-and-run`.

Загрузчик запускает приложение из `/usr` внутри комплектного userspace: WebKitGTK в сборке Amazon Linux использует относительные пути к процессам и helper-библиотекам. Исходный каталог при этом остаётся примонтированным по прежнему абсолютному пути.

Для сохранения ключа в Alpine нужен также пользовательский Secret Service на хосте и доступный D-Bus session bus. Не устанавливайте keyring-демон внутрь AppImage.

Домашний каталог, текущий каталог, `/mnt`, `/media` перенаправляются к файлам хоста. Shell работает с программами комплектного glibc-userspace, не с нативным Alpine `apk` окружением. PRoot не является security sandbox; WebKit process sandbox отключён из-за ptrace. Не запускайте как root и не используйте для недоверенных web-страниц.

Сборка и загрузчик проверяются без визуальных тестов. Это не проверка на вашем настоящем Alpine desktop, Android-устройстве или Wi-Fi роутере.

## Компоненты и дизайн

Использованы оригинальные React-компоненты Beautiful UI (https://www.beautifului.dev/), MIT, автор Shane Levine. Исходная версия: repository `slev12397/beautiful-ui`, commit `44a274e598395ab61e7c96c26fda2758780253b7`.

LoadingState, ThinkingState, StreamingText, ToolChips, ApprovalCard, RecommendationCard, CodeBlock, GlideMenu и атомы Button / EntityChip / ValuePill адаптированы для реальных событий. Галерейные таймеры tool trace не используются в production-потоке. PromptBar и ChatComposer из Beautiful UI **не импортированы**; composer собственный, из согласованного макета.

Geist UI Icons с тонкой обводкой, Geist с Inter для кириллицы. Темы: системная, светлая, тёмная, графит, бумага. Меню раскрываются от точки кнопки, диалоги анимируют открытие и закрытие. Поддерживается reduced motion. Визуальные тесты не запускались по просьбе пользователя.

## Сборка из исходников

Node 22+ / npm, Rust stable, GTK3 + WebKitGTK 4.1 headers на Linux. Android: JDK 17+, SDK 36, NDK 27.2.12479018.

```sh
npm ci
npm test # Rust + React structural/component/IPC tests. Без браузера и скриншотов.
npm run build
npm run tauri -- build --bundles appimage
# For direct Cargo release builds, include Tauri's production asset protocol:
cargo build --release --manifest-path src-tauri/Cargo.toml --features custom-protocol
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/Android/Sdk
export NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
rustup target add aarch64-linux-android
npm run tauri -- android build --target aarch64 --apk
scripts/sign-apk.sh src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk Velocity-Harness-android-arm64.apk
```

Не запускайте `android init` без необходимости: проект уже сгенерирован, включая permissions и discovery-настройки. `local.properties`, keystore и build output не входят в архив. APK в чате подписан тем же development ключом, что предыдущая версия; приватный keystore не передаётся. Для собственного релиза создайте и безопасно сохраните свой ключ.

16 Rust-тестов проверяют совместимые API, approvals, отсутствие ключей в metadata/истории, реальные SSE-дальты обеих схем, cancellation, fragmented tool arguments, сохранение проектов, snapshots diff и запрет устаревшей записи, LAN auth. React-тесты проверяют общий approval, diff вместо JSON, shell warning, сохранение DOM слова, смену разрешений без нового run и переход в настройки без потери чата. Дополнительно проверены невизуальные сценарии мобильного меню (открытие, фон, Escape, inert), portal-toast и обновление его координат при изменении visualViewport. Это не end-to-end тест с вашим провайдером или настоящим телефоном. Android Keystore не тестировался на физическом устройстве; в сборочном Linux нет пользовательского Secret Service, поэтому его реальное разблокирование нужно проверить на вашем компьютере.

Пока нет MCP plugins, автоматики, голосового ввода, автоматического context compaction, загрузки весов или криптографически защищённого vault. Работает один активный run на backend, до 12 шагов agent loop. Ошибка провайдера сохраняет текст; повторный запуск создаёт новый ответ и не означает гарантированный resume того же inference.
